# Integration failure ledger

Use this ledger when a branch stalls or a test appears to pass for the wrong reason. Each rule came from a repeatable failure mode, not a preferred style.

| Symptom | Cause | Rule |
|---|---|---|
| Appium setup consumes the task, a preinstalled WDA cannot be trusted, an overlay remains visible, or orphan processes survive. | WDA became the default route and process ownership was unclear. | Start with CoreDevice. Authorize WDA only as a maintenance observer or selector exception. Track owned processes, inspect for overlays, and stop those processes explicitly. |
| CoreDevice reports success but the requested view is absent. | Transport acceptance was treated as rendered evidence. | Record acceptance as dispatch evidence only. Require an exact-scope user visual pass or direct inspection of an authorized screenshot for promotion. |
| A candidate becomes “proven” after documentation review, fake execution, or screenshot capture. | Indirect evidence was promoted by inference. | Derive availability from admissible evidence. A screenshot earns nothing until its pixels are inspected and the expected state is adjudicated. |
| A selector passes once, then hits the wrong control or a stale element. | Cardinality was broad, or the element survived a state transition only in the client cache. | Require two unchanged exact-cardinality observations. Use a stable accessibility ID or bounded predicate and re-find after each state change. |
| Full XML dumps, timing tricks, or benchmark loops seem to rescue a selector. | Volume and repetition hid an unstable identity. | Inspect the smallest bounded subtree or screenshot needed. Benchmarks measure an admitted route; they do not establish selector authority or compatibility. |
| Ordinary users must know opcodes, selectors, lab plans, WDA lifecycle, or setup ceremony. | Maintenance machinery leaked into the operator interface or a cumulative skill became the command catalogue. | Expose full-word one-call semantics in the app-local skill. Keep lab and transport mechanics in maintenance docs, never in a router or cumulative app skill. |
| A deep link opens the wrong place, or a Shortcuts route uses a plausible but nonexistent action name. | A scheme, path, field, or action name was guessed. | Require first-party documentation, AASA association, an exact generated link, or an exact proven private literal. Source shape permits testing; it does not prove rendering. |
| Cleanup closes an unrelated Safari tab. | Ownership was inferred from tab position or count. | Close only a tab whose exact creation and identity belong to the task. Leave ambiguous tabs untouched. |
| A file-share callback is reported as successful opening on the iPad. | Mac-side AirDrop completion was confused with recipient receipt and app state. | Report host completion only. Keep receipt and exact-file opening pending until separately observed. |
| A new run imports old code, reads an old artifact, or mistakes an old screenshot/process for current evidence. | The interpreter, generated files, screenshot set, kernel state, or observer process survived structural work. | Start a fresh interpreter after moves. Inventory and remove task-owned artifacts, adjudicate screenshots once, and audit owned processes before and after observation. |
| A valid new URL is accepted but Maps keeps showing the previous view. | Warm app state swallowed or absorbed the launch. | Add terminate-existing behavior only to the affected app route after evidence requires it. Maps has such evidence; it is not a shared default. |
| Documentation and checkpoints claim an old availability count or an obsolete boundary. | A promotion or reorganization updated authority without its direct assertions and summaries. | Search authoritative docs and tests for the old claim, then update only the owning paragraphs and checkpoints. Re-run in a fresh interpreter. |
| Release review becomes a giant dirty tree with no clear completion point. | Several applications or architectural changes were opened before one boundary closed. | Finish one app-sized change, its tests, cleanup, and report before starting the next. Use a short path for clean-copy checks so Unix-socket limits do not create a false repository failure. |
| A documented custom scheme is accepted but the previous app view remains visible. | Upstream source described parsing, but the installed build/profile did not render the payload. | Record exact-profile negative visual evidence and mark the route incompatible; do not retry it into apparent success. |
| A first launch stops at notifications, What’s New, account, or permission UI. | The application has an irreducible human gate unrelated to route construction. | Leave the gate to the user. Record app visibility separately from post-gate readiness and continue only after the user chooses. |
| Screenshot observation of Photos, Messages, or Mail reveals unrelated private content around the tested surface. | The app uses a split/library view, so a harmless route does not make the whole screen non-sensitive. | Avoid screenshots where a narrower proof exists. If one is necessary and authorized, inspect only the deciding state, delete it immediately, retain no content, and never quote it. |
| AirDrop waits until timeout or loses its callback. | Recipient selection, receipt, or helper response did not complete within the bounded attempt. | Return `uncertain`, retain the private recovery snapshot, stop the helper, and never replay that transfer automatically. |
